# Методология скоринга

> Демонстрационная модель. Не оферта. Не заменяет коммерческую проработку.
> Все числовые параметры — стартовые экспертные оценки, подлежат калибровке
> на исторической выборке закрытых сделок.

## 1. Принцип

Для каждой пары **(ведомство × продукт Сбера)** считается скор потенциала
0–100. Скор — это ответ на вопрос «насколько *сейчас* Сберу имеет смысл
заходить в этот сегмент этого ведомства». Скор ≠ прогноз выручки.
Скор ≠ вероятность сделки. Скор — приоритизатор внимания аналитика.

Тиры:
- `>= 65` — **HIGH**, ставить в проработку немедленно
- `45–64` — **MEDIUM**, держать в поле зрения
- `< 45` — **LOW**, фиксируем, не тратим ресурсы

## 2. Формулы

### 2.1 Классические продукты (core)

```
score = (f_demand·0.30 + f_position·0.25 + f_size·0.20
       + f_sent·0.15 + f_comp·0.10) · 100
```

Логика весов: спрос (30%) и позиция Сбера (25%) — главное. Масштаб клиента
(20%) — сколько денег вообще в игре. Сентимент (15%) — открытость. Конкуренция
(10%) — насколько тесно в сегменте.

### 2.2 Экосистемные продукты (eco)

```
anchor = 0.15 если у ведомства есть зарплатный сигнал Сбера, иначе 0
score  = (f_size·0.35 + f_position·0.30 + f_demand·0.10
       + f_sent·0.05 + f_comp·0.05 + anchor) · 100
```

Логика: экосистема продаётся *личному составу* поверх зарплатного проекта.
Поэтому масштаб штата (35%) и уникальность Сбера (30%) — доминируют.
Anchor +15 п. — бонус, если Сбер уже держит хоть часть зарплатника
(есть на кого «нанизать» подписку).

Финально: `score = min(score, 100)`.

## 3. Множители — что это и откуда берётся

### 3.1 `f_demand ∈ [0, 1]` — сила спроса из прессы

```
f_demand = min(demand_signal / 20, 1)
```

**`demand_signal`** — целочисленный счётчик, накапливается по словарю
событийных триггеров. Каждый триггер даёт вклад в demand_signal только
тех продуктов, к которым он привязан.

Событийный словарь (расширяется, см. `sources/triggers.yaml`):

| Паттерн в тексте (regex/LLM-классификатор) | Триггерит продукт | Вклад | Тип сигнала |
|---|---|---|---|
| «набор \| комплектование \| вакансии» + число штата | consumer_loan, salary_budget, eco_sberprime | +3 за каждые 1000 чел. | official |
| «повышение денежного довольствия \| индексация \| надбавка» | consumer_loan (рефинанс), premium_service | +5 | official |
| «жилищный сертификат \| субсидия \| НИС \| накопительно-ипотечная» | mil_mortgage | +4 | official |
| «удалённый гарнизон \| застава \| Арктика \| Крайний Север» | eco_zdorovie, eco_samokat_kuper | +3 | official/expert |
| «штраф \| госпошлина \| исполнительное производство \| взыскание» + сумма | acquiring_fines | +4 | official |
| «цифровизация \| электронный документооборот \| ИИ \| GigaChat» | gigachat_ai, cloud | +3 | official/industry |
| «кибератака \| утечка \| DDoS \| инцидент ИБ» в контексте госсектора | cybersec | +5 | industry |
| «телемедицина \| врач на удалёнке \| дистанционная консультация» | eco_zdorovie | +4 | official/user |
| «социальный пакет \| льготы личному составу \| соцподдержка» | eco_sberprime, npf_insurance | +3 | official/expert |
| Профильный праздник ведомства в ближайшие 30 дней | Все focus-продукты плейбука | +2 | holiday |
| Тендер на банковское обслуживание на zakupki.gov.ru | Соответствующий core-продукт | +7 | official |
| Негативный отзыв в UGC на продукт банка-конкурента | Тот же продукт у Сбера (через f_position) | +0.05 к f_position | user |

Верхняя планка `demand_signal / 20 = 1` намеренно низкая: 20 триггеров
за окно наблюдения (30 дней) — это уже «горячий» сегмент.

### 3.2 `f_sent ∈ [0, 1]` — сентимент корпуса

```
f_sent = (avg_sentiment + 1) / 2
```

**`avg_sentiment ∈ [-1, +1]`** — среднее по публикациям, попавшим в пару
(ведомство × продуктовый сегмент), а НЕ по ведомству в целом. Это
принципиально: одно и то же ведомство может быть на подъёме в теме
цифровизации и в минусе в теме социалки — усреднять их бессмысленно.

**Правила разметки:**

1. Метод — LLM (GigaChat / локальная модель) по трёхбалльной шкале
   `−1 / 0 / +1` с явной системной инструкцией:

   > «Оценивай тональность публикации в контексте *способности ведомства
   > платить / удовлетворённости личного состава / открытости к внешним
   > сервисам*, а НЕ общий тон новости. Пример: «в части перебои с
   > довольствием» — это -1 для consumer_loan (снижается платёжеспособность),
   > но 0 для gov_dbo (никак не влияет на бюджетные потоки ведомства).»

2. Минимум **5 публикаций** для валидного среднего. При меньшем
   количестве — `f_sent = 0.5` (нейтраль), в UI ячейка помечается
   значком «⊘ мало данных».

3. Разметку хранить в `data.json` в поле
   `sentiment_evidence: [{url, snippet, score, model, timestamp}]` —
   для аудита и прозрачности.

4. Раз в квартал — ручная сверка 100 случайных публикаций для
   калибровки модели.

### 3.3 `f_position ∈ [0, 1]` — позиция Сбера в сегменте

Базовое значение задано в каталоге продуктов (`data.json → products`).
Значения — экспертные, скорректированы по данным о долях рынка из
`market_analytics` (Frank RG, Эксперт РА).

**Актуальные значения (август 2026):**

**Поправки по типу ведомства (применяются поверх базы):**

- `minoborony` + (salary_budget \| mil_mortgage): −0.10
- `minoborony` + npf_insurance: −0.15 (СОГАЗ — кэптив МО)
- (fssp \| fts \| mvd) + acquiring_fines: +0.10
- (sledkom \| prokuratura) + (cloud \| gov_dbo): −0.05

**Динамические поправки (из UGC):**

- За каждый негативный отзыв на банк-конкурент по этому же продукту
  в источниках `social_ugc` за последние 30 дней: `f_position += 0.02`
  (максимум +0.10). Учитывать только отзывы с оценкой ≤ 2/5 и
  верифицированной покупкой.

### 3.4 `f_size ∈ [0, 1]` — масштаб клиента

```
f_size = min(штат / 30 000, 1)
```

Штат берётся из реестра ведомств (`data.json → agencies`).
Порог 30 000 — эмпирический: выше этого штата масштабный эффект
экосистемы уже полностью реализован.

### 3.5 `f_comp ∈ [0, 1]` — поправка на конкуренцию

**Было (в исходном промпте):**
```
f_comp = 1 - (кол-во конкурентов / 4) · 0.5
```
Проблема: все конкуренты равны, что неправда (ВТБ ≠ Почта Банк).

**Стало (взвешенная версия):**
```
competitor_pressure = Σ(доля_рынка_конкурента_i)   для i ∈ конкуренты сегмента
f_comp = 1 - min(competitor_pressure, 0.8) · 0.625
```

Доли рынка — из блока `market_shares` в `data.json`, обновляются раз в
квартал. Верхний ограничитель 0.8 не даёт f_comp упасть ниже 0.5 (даже
в тотально монополизированном сегменте есть шанс отыграть нишу).

## 4. Пересчёт при изменении данных

**Триггеры пересчёта скора для ячейки:**
1. Появилась новая публикация в её паре (ведомство × продукт).
2. Обновилась таблица `market_shares` (квартально).
3. Обновилась таблица `competitor_matrix` (еженедельно, через
   `scripts/refresh_competitors.py`).
4. Изменился штат ведомства (редко).

Пересчёт — идемпотентная функция от текущего состояния `data.json`.
Историю скоров хранить в `data/history/YYYY-MM-DD.json` для трендов.

## 5. Плейбук vs скоринг — как не путать в UI

- **Скоринг** — расчёт по публикациям. Числовой, воспроизводимый,
  ссылки на источники. Зона доверия — «формула».
- **Плейбук** — экспертная тактика (`playbook.py` / `data.json →
  playbooks`). Мнение модели. Зона доверия — «эксперт».

В UI визуально разделены:
- Скоринговые числа — зелёная/жёлтая/серая заливка тира.
- Плашка «Самое востребованное» — акцентный градиент зелёно-фиолетовый,
  явно помечена «★ Тактика» (не «★ Данные»).

Кнопка «?» рядом со скором ячейки открывает модалку с разложением
формулы и списком публикаций, попавших в demand_signal.

## 6. Ограничения модели

Явно фиксируем, что модель НЕ может:

- Предсказать факт заключения контракта. Скор HIGH ≠ сделка.
- Учесть личные связи, лоббизм, аппаратные решения — они не в прессе.
- Работать с закрытыми ведомствами (ФСБ, СВР) — публикаций критически
  мало, скор считается на основе гипотез плейбука с явной пометкой
  `low_confidence: true`.
- Отличить реальное намерение закупить от плановой ротации бюджета.
- Заменить коммерческую проработку с ЛПР ведомства.

## 7. План калибровки

**Итерация 1 (текущая):** экспертные веса, публичные аппроксимации долей
рынка.

**Итерация 2 (после накопления 100+ размеченных пар «скор → факт сделки»):**
- Линейная регрессия весов на исторической выборке.
- Отдельные модели для core и eco (структура факторов разная).
- Метрика качества — Spearman correlation между скором и рангом
  закрытых сделок.

**Итерация 3:** переход от статичного словаря триггеров к LLM-классификатору,
дообученному на размеченном корпусе публикаций.
